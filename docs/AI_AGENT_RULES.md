# AI Agent Rules

Эти правила обязательны для AI-агентов, работающих над Lifera.

## Базовые правила работы

1. Сначала анализировать текущую структуру проекта, затем менять файлы.
2. Не менять архитектуру без отдельного запроса.
3. Не создавать дублирующие компоненты, если уже есть подходящий компонент или паттерн.
4. Не добавлять новые библиотеки без объяснения причины и альтернатив.
5. Не менять схему базы данных без отдельной задачи.
6. Не создавать Supabase-миграции без явного разрешения.
7. Не трогать авторизацию без отдельной задачи.
8. Не хранить секреты в коде.
9. Не использовать API-ключи на клиенте.
10. Не вызывать OpenAI API напрямую из frontend.
11. После каждой задачи показывать список измененных файлов.
12. После каждой задачи объяснять, что было сделано.
13. Если есть риск сломать проект - сначала предупредить.
14. Каждая задача должна быть маленькой и проверяемой.
15. После изменений предлагать команды для проверки.

## Правила архитектуры

- Next.js используется как основной full-stack framework.
- React и TypeScript обязательны для frontend.
- Tailwind CSS и shadcn/ui используются как основа UI.
- Supabase PostgreSQL используется как основная база данных.
- Supabase Auth используется как базовая авторизация.
- RLS обязателен для пользовательских данных.
- Backend-логика не должна расползаться по UI-компонентам.
- XP, достижения и AI-запросы должны обрабатываться на серверной стороне.

## Правила безопасности

- Никогда не добавлять `.env` с реальными секретами.
- Клиентский код может использовать только публичные ключи, безопасные для браузера.
- OpenAI API key, Stripe secrets и service role key должны оставаться только на backend.
- Health и capital данные считаются чувствительными.
- AI должен получать минимально необходимый контекст.

## Правила разработки

- Не создавать приложение, страницы или компоненты, если задача только про документацию.
- Не устанавливать зависимости без отдельного подтверждения.
- Не создавать `package.json`, если проект еще не инициализирован и пользователь этого не просил.
- Сначала использовать существующие паттерны проекта.
- Новые файлы должны иметь понятное назначение.
- Изменения должны быть ограничены текущей задачей.

## Формат отчета после задачи

После выполнения задачи агент должен сообщить:

- какие файлы изменены;
- что именно сделано;
- какие проверки выполнены;
- какие проверки рекомендуется выполнить дальше;
- какие риски или открытые вопросы остались.
