# AI Coach Logic

## Назначение AI Coach

AI Coach - помощник, который помогает пользователю перейти от размытого намерения к конкретному действию. Он не должен принимать решения вместо пользователя, ставить медицинские или финансовые диагнозы, обещать результат или заменять профессиональную консультацию.

## Задачи AI Coach

В первой версии AI Coach решает практические задачи:

- помогает сформулировать цель;
- разбивает цель на задачи;
- предлагает привычки под выбранную сферу жизни;
- анализирует прогресс на основе ограниченных данных;
- предлагает следующий шаг.

## Какие данные AI может анализировать

AI может получать только минимально необходимый контекст:

- выбранные сферы жизни;
- название и описание конкретной цели;
- связанные задачи и их статусы;
- привычки и общую регулярность;
- общий XP и достижения;
- историю предыдущих AI-рекомендаций по конкретному сценарию.

В Core MVP AI не анализирует Health, Capital и Skills. Эти данные можно подключать только после отдельного проектирования приватности, согласия пользователя и prompt-контрактов.

## Какие данные не должны передаваться без необходимости

Без явного сценария и понятной причины AI не должен получать:

- email и идентификаторы пользователя;
- платежные данные;
- подробные финансовые записи;
- чувствительные health logs;
- приватные заметки, не относящиеся к запросу;
- полную историю действий пользователя.

## Функции первой версии

- Goal Builder: помогает уточнить цель и сделать ее измеримой.
- Goal Breakdown: предлагает список задач для цели.
- Habit Suggestion: предлагает 1-3 привычки под цель или сферу жизни.
- Progress Review: кратко анализирует прогресс по задачам и привычкам.
- Next Step: предлагает один следующий практический шаг.

Для первой реализации приоритетнее Goal Builder, Goal Breakdown и Habit Suggestion. Progress Review и Next Step можно добавить после того, как появятся реальные данные о выполненных задачах и привычках.

## Функции на будущее

- Долгосрочная AI-память.
- Персональные еженедельные обзоры.
- Автоматическое выявление застоя.
- Интеграции с календарем.
- Голосовой ассистент.
- AI-агенты для планирования недели.
- Более глубокая аналитика здоровья и капитала с дополнительными ограничениями безопасности.

## Безопасный вызов OpenAI API

OpenAI API должен вызываться только через backend-слой:

- Next.js Route Handlers;
- Server Actions;
- серверные сервисы;
- защищенные переменные окружения на Vercel.

Frontend отправляет только пользовательский запрос и идентификаторы релевантных объектов. Backend проверяет сессию, применяет RLS/доступ, собирает минимальный контекст и только после этого вызывает OpenAI API.

## Почему нельзя вызывать AI API напрямую из frontend

Прямой вызов с клиента запрещен, потому что:

- API-ключ может быть раскрыт в браузере;
- нельзя надежно ограничить расходы;
- сложно контролировать, какие данные отправляются в модель;
- пользователь может обойти клиентские ограничения;
- невозможно централизованно логировать и модерировать запросы.

## Ограничение расходов на AI

В первой версии нужно предусмотреть:

- лимиты запросов на пользователя в день;
- лимиты по типам AI-сценариев;
- короткий контекст вместо полной истории;
- хранение summary вместо длинных prompt;
- логирование стоимости или количества токенов;
- отключение дорогих функций для бесплатного плана в будущем.
- отказ от потоковой генерации и длинной истории на старте, если это усложняет контроль расходов.

## Хранение истории рекомендаций

Рекомендации хранятся в `ai_recommendations`:

- тип рекомендации;
- краткое summary запроса;
- ответ AI;
- статус: suggested, accepted, rejected, applied;
- связь с целью или другим объектом;
- дата создания.

Это позволяет показывать историю, измерять полезность AI и начислять XP только за примененные рекомендации.
