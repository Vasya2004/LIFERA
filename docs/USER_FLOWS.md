# User Flows

## Регистрация пользователя

Цель пользователя: создать личный аккаунт и получить доступ к Lifera.

Шаги пользователя:

1. Открывает `/auth`.
2. Регистрируется через email.
3. Подтверждает вход.
4. Попадает в onboarding.

Что происходит в системе:

- Supabase Auth создает пользователя.
- Создается запись в `profiles`.
- Пользователь получает защищенную сессию.

Данные:

- Создаются: `auth.users`, `profiles`.
- Обновляются: время последнего входа.

Результат: пользователь авторизован и направлен к первичной настройке.

Примечание: OAuth-провайдеры можно добавить позже, но они не обязательны для Core MVP.

## Onboarding

Цель пользователя: настроить Lifera под свои жизненные приоритеты.

Шаги пользователя:

1. Переходит на `/onboarding`.
2. Заполняет имя и базовые предпочтения.
3. Выбирает сферы развития.
4. Завершает настройку.

Что происходит в системе:

- Профиль получает статус завершенного onboarding.
- Выбранные сферы связываются с пользователем.

Данные:

- Обновляется: `profiles`.
- Создаются или связываются: `life_areas`.

Результат: пользователь попадает на dashboard с персонализированной структурой.

## Выбор сфер развития

Цель пользователя: указать, какие области жизни он хочет отслеживать.

Шаги пользователя:

1. Видит список сфер: здоровье, карьера, финансы, обучение, отношения, личное развитие.
2. Выбирает приоритетные сферы.
3. При необходимости задает собственную сферу.

Что происходит в системе:

- Сохраняются активные сферы пользователя.
- Эти сферы используются при создании целей, задач, привычек и прогресса.

Данные:

- Создаются или обновляются: `life_areas`.

Результат: пользователь видит выбранные сферы в dashboard и формах создания.

## Создание первой цели

Цель пользователя: зафиксировать долгосрочный результат.

Шаги пользователя:

1. Открывает `/goals`.
2. Нажимает создание цели.
3. Указывает название, описание, сферу жизни, срок и приоритет.
4. Сохраняет цель.

Что происходит в системе:

- Создается запись цели.
- Может создаться XP-событие за первую цель.
- Проверяется достижение "Первая цель создана".

Данные:

- Создается: `goals`.
- Создается: `xp_events`.
- Возможно создается: `user_achievements`.

Результат: пользователь видит цель в списке и на dashboard.

## Декомпозиция цели на задачи

Цель пользователя: превратить цель в понятный план действий.

Шаги пользователя:

1. Открывает цель.
2. Выбирает ручную декомпозицию или помощь AI Coach.
3. Принимает предложенные задачи.
4. Сохраняет план.

Что происходит в системе:

- Создаются задачи, связанные с целью.
- При использовании AI сохраняется рекомендация.

Данные:

- Создаются: `tasks`.
- Возможно создается: `ai_recommendations`.

Результат: у цели появляется набор конкретных следующих действий.

## Создание привычки

Цель пользователя: добавить регулярное действие.

Шаги пользователя:

1. Открывает `/habits`.
2. Создает привычку.
3. Выбирает сферу жизни, расписание и целевую частоту.
4. Сохраняет привычку.

Что происходит в системе:

- Создается привычка.
- Она появляется в ежедневном списке и dashboard.

Данные:

- Создается: `habits`.

Результат: пользователь может ежедневно отмечать выполнение привычки.

## Выполнение задачи

Цель пользователя: закрыть конкретное действие.

Шаги пользователя:

1. Открывает `/tasks` или dashboard.
2. Находит задачу.
3. Отмечает ее выполненной.

Что происходит в системе:

- Статус задачи меняется на `completed`.
- Начисляется XP.
- Пересчитывается прогресс связанной цели.
- Проверяются достижения.

Данные:

- Обновляется: `tasks`.
- Создается: `xp_events`.
- Возможно создается: `user_achievements`.

Результат: пользователь видит выполненную задачу, прирост XP и обновленный прогресс.

## Отметка привычки

Цель пользователя: зафиксировать выполнение регулярного действия.

Шаги пользователя:

1. Открывает dashboard или `/habits`.
2. Отмечает привычку за текущий день.
3. Видит streak и XP.

Что происходит в системе:

- Создается запись в `habit_logs`.
- Обновляется streak.
- Начисляется XP.
- Проверяются достижения за регулярность.

Данные:

- Создается: `habit_logs`.
- Обновляется: `habits`.
- Создается: `xp_events`.

Результат: пользователь видит отметку дня, streak и игровой прогресс.

## Получение XP

Цель пользователя: видеть накопительный результат своих действий.

Шаги пользователя:

1. Выполняет полезное действие.
2. Получает уведомление или визуальный feedback.
3. Видит изменение уровня или прогресса.

Что происходит в системе:

- Создается XP-событие с причиной начисления.
- Общий XP пользователя рассчитывается из событий.

Данные:

- Создается: `xp_events`.

Результат: пользователь понимает, за что получил прогресс.

## Получение достижения

Цель пользователя: получить награду за milestone.

Шаги пользователя:

1. Выполняет условие достижения.
2. Получает сообщение о новом достижении.
3. Видит его в `/achievements`.

Что происходит в системе:

- Система проверяет условия.
- Создается запись в `user_achievements`.

Данные:

- Читается: `achievements`.
- Создается: `user_achievements`.

Результат: пользователь видит новое достижение и дату получения.

## Просмотр прогресса на dashboard

Цель пользователя: быстро понять текущее состояние Lifera.

Шаги пользователя:

1. Открывает `/dashboard`.
2. Видит активные цели, задачи на сегодня, привычки, XP, streak и рекомендации.
3. Переходит в нужный раздел.

Что происходит в системе:

- Загружаются агрегированные пользовательские данные.
- Отображаются только данные текущего пользователя.

Данные:

- Читаются: `goals`, `tasks`, `habits`, `habit_logs`, `xp_events`, `ai_recommendations`.

Результат: пользователь получает обзор и понимает следующий шаг.

## Запрос рекомендации у AI Coach

Цель пользователя: получить помощь с целью, задачей или прогрессом.

Шаги пользователя:

1. Открывает `/ai-coach`.
2. Выбирает сценарий: сформулировать цель, разбить цель, предложить привычку, проанализировать прогресс.
3. Отправляет запрос.
4. Получает рекомендацию.
5. Принимает или отклоняет предложение.

Что происходит в системе:

- Backend собирает минимально нужный контекст.
- Route Handler или Server Action вызывает OpenAI API.
- Результат сохраняется в `ai_recommendations`.

Данные:

- Читаются релевантные пользовательские записи.
- Создается: `ai_recommendations`.
- Возможно создаются: `tasks`, `habits` при принятии рекомендации.

Результат: пользователь получает практический следующий шаг.

## Редактирование профиля

Цель пользователя: обновить персональные настройки.

Шаги пользователя:

1. Открывает `/profile`.
2. Меняет имя, аватар, timezone или предпочтения.
3. Сохраняет изменения.

Что происходит в системе:

- Обновляется профиль.
- Настройки используются в dashboard, onboarding и уведомлениях.

Данные:

- Обновляется: `profiles`.

Результат: пользователь видит актуальные данные профиля.
